Culling — bursts and blurry pictures are set aside

Import wizard, step 1 (the same in “Add pictures”, from the device and from Immich). Right after the downscale, each picture is checked. Of a burst, only the sharpest stays; blurry shots are set aside. Set-aside pictures sit below the strip in groups and are not in the slideshow. One tap on + takes one in; “Take all in” undoes the whole cull. Try it below, or press Replay import. The images are generated.

How it works

  • When: each picture is checked as soon as it is downscaled, on its 480 px thumbnail, in a worker. The check is this screen's work, so it gets the inline progress line with a count, and Next waits for it as it waits for the downscale.
  • Burst: pictures taken at most 2 s apart (chained), whose 64-bit difference hashes differ in at most 10 bits. The sharpest one stays; ties go to the earliest. Sharpness is the variance of the Laplacian on the grey thumbnail.
  • Blurry: sharpness below a fixed floor and below a third of this import's median, so a whole set shot in dim light is not emptied. A burst's kept picture is never set aside as blurry, and if every picture would go, none does.
  • Set aside means not stored: Next drops them, so they cost no storage. + moves one into the strip at its capture-date place; from then on it is an ordinary picture (✕ removes it as before). There is no model or .glissando format change: the slideshow only holds what was kept.
  • No switch in the settings: “Take all in” is the way out, per import. Exact duplicates keep their own lemon notices (ADR-0016) and are skipped before the check.
  • On the phone the groups wrap in rows of three; + is a 44 px target and has the label “Take in picture from <date>”.
