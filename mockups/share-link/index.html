Share a server slideshow by link

A slideshow on your Glissando server gets a link that anyone can open in a browser. They can watch it, but they can't change anything and can't see your Immich. Try it: “Share link” in the info panel, then “Open as viewer” to see what the recipient gets. The “Concept” tab has the 4K picture source measurements and the decisions that are still open.

How it works

  • Only server slideshows. Their pictures live in Immich and the server already stores the slideshow and its music, so the link can serve everything without a device being online. A device slideshow shows the row dimmed: “Save it on your Glissando server to share it by link.”
  • Where: the info panel, under the server row. Two placements to compare: its own row, or a second line inside the server row. Once the link is on, the row says “Shared by link” and shows the start of the address with a mint “On” pill.
  • The sheet (a dialog on desktop, a bottom sheet on the phone). Off: what the link does in three lines, then “Create link”. On: the address with “Copy”, “Share …” (the system share menu, on phones and Safari), “Open as viewer”, and a QR code for a phone in the same room. “Turn off link” asks before it acts. Sharing again makes a new link, and the old one stays dead.
  • The link: https://<your host>/s/<token>. The token is 128 random bits (22 characters), stored only as a hash. It stays valid until you turn it off, and it is live, so an edit shows up the next time the viewer starts the slideshow.
  • The address is the one Glissando is open at. If that is a home network address (an IP, .local, plain HTTP), the sheet says the link only works at home.
  • The recipient sees a start card (title, pictures, length, Play), then the slideshow with Ken Burns, transitions, captions and music, using the same player as the web page export, which loads the pictures a few ahead. If a picture is late, a small “Loading” chip appears. If the link is off, the page says so without the title. If the server can't be reached, it offers “Try again”.
  • What never reaches the recipient: Immich ids, file names, places, dates of the photos, other slideshows. Pictures are fetched by their position in the slideshow (/api/share/<token>/pictures/<n>).
  • Your setup: Traefik and Authelia stay as they are. One Authelia bypass rule for /s/ and /api/share/, written up in the self-hosting guide. Inside the container, Caddy asks the Node service whether a token is valid before it fetches a picture from Immich (forward_auth), so the Immich key stays with Caddy.

Immich's preview size is the short edge, so 2160 always covers what a 3840×2160 frame shows of a picture: a 3:2 landscape fills the height at 3240×2160, a portrait needs only 1440 of its 2160 width. A 1920×1080 picture is never scaled up. The setting has no upper limit. Alpha is flattened to JPEG. Measured in a throwaway Immich with generated images; your Immich was not touched.
