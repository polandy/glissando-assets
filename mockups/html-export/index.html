Save a slideshow as a web page

The slideshow screen. “Web page” under “Save as” creates one .html file with the downscaled pictures, the music and a small player: it plays offline in a browser, at a fraction of the video's size. “Open it” in the finished sheet, or “Exported page”, shows what the recipient sees. The run is a time lapse. “Test this device” downloads a real sample file to try opening on the iPad, an Android phone and a computer.

How it works

  • Where: the info panel. Under “Play”, “Save as” offers Video and Web page side by side (the “Info panel” switch also shows three stacked buttons). “Web page” opens a dialog, or a bottom sheet on the phone.
  • Two sizes: Small, 1280 px on the long edge, to send in a message; Sharp, 1920 px, for a computer, tablet or TV. Each shows its size, and a bar compares it with the 1080p video.
  • Fast: Glissando only scales down 50 pictures and writes one file, which takes seconds instead of the video's minutes. No WebCodecs, so it works in every browser that runs Glissando.
  • Finished: the same targets as the video. Chrome/Edge save where you chose at the start, Safari offers “Share …”, Firefox downloads. Plus “Open it”, which shows the page as the recipient will see it.
  • What the recipient sees: a start card (title, pictures, length, a big Play button, since browsers only play music after a tap), then the slideshow full screen with Ken Burns, transitions, captions and the music with its trim and fades, exactly as in Glissando. Controls appear on a tap or mouse move: play/pause, a timeline, mute, full screen. At the end, “Play again”.

Base64 costs a third on disk, but almost nothing once sent compressed: the gzipped one file is as big as the deflated zip. WebP would have been 3–4 × smaller on these generated pictures (on real photos usually about 30 %), but Safari's canvas cannot write WebP, so the export would turn out differently depending on the browser. 2560 px is too big to send as mail (about 25 MB limit).

From a zip, Chromium and Safari refuse the pictures to WebGL, so Glissando's player could only fall back to the DOM. The zip also has to be unpacked first: Windows opens a zip like a folder and then shows the page without its pictures, and on Android a file opened from a share or the Files app has no folder around it. Not measurable in CI: iOS Files (its preview is known to show HTML without scripts) and real Android phones. The “Test this device” tab covers both.

Proposal

  • One self-contained .html: one file that plays wherever it is opened, by double-click, from a mail or from Downloads, and WebGL works because the pictures are inside it. The third of extra size on disk mostly disappears when it is sent.
  • Glissando's own player engine (src/player/), built as a second, standalone bundle: 39 KB, 12.5 KB gzipped, plus the caption font (Instrument Sans, 36 KB). It reads the same slideshow JSON as the app, so music trim and fades, captions, each picture's own Ken Burns, duration and transition all carry over unchanged, with no second implementation to keep in step. The page only adds the start card, the controls and the end card, in plain TypeScript without Svelte.
  • Pictures scaled down off the main thread (as when preparing pictures, ADR-0014) to JPEG q 0.85 at 1280 or 1920 px on the long edge, never scaled up. The music goes in as its original bytes, and the player applies trim and fades. Re-encoding only the part that plays would be smaller, but there is no AAC encoder in Firefox or in Chromium on Linux.
  • Recorded as ADR-0017: one file over a zip, JPEG over WebP, the player engine reused.

Open for you

  • iPhone / iPad: please run “Test this device” there. If Files shows the page without scripts, the sample's no-script fallback (a CSS slideshow with an audio control) decides whether that is worth carrying: it costs no size if the pictures go in as data: images.
  • Info panel: “Save as: Video | Web page” (my pick: compact, and the two read as a pair) or three stacked buttons?
  • Sizes: Small 1280 and Sharp 1920 (my pick), or only one size?

Does an exported page play on this device?

This builds a small real export here in the browser: six generated pictures (no photos), 20 s of generated music, captions, and the player. The pictures sit inside the file as data: images, so the same file also carries a no-script fallback: a CSS slideshow with the music as a plain audio control. The page reports on screen what worked. Nothing leaves the device.

  1. iPhone / iPad: download, then open it from the Files app (Downloads). Try a tap on the file, and also long press → Share → Safari or Chrome if offered. For the zip: tap to unpack, open the folder, tap index.html.
  2. Android: download, then open it from the notification, from Files / Downloads, and from Chrome's Downloads list.
  3. Computer: download, double-click it (opens via file://). For the zip: once without unpacking (Windows opens into the zip), once unpacked.
  4. Each time, note what the page says at the top (“Scripts running …”, or the no-script banner) and whether the pictures move and the music plays. A screenshot in the chat is enough.
The sample is built when you press a button (about 2.5 MB).
