Where does the picture-frame set-up go?

Today a "Picture frame" card sits above everything on the start page (only while the server library is on). Glissando's main job is creating and playing slideshows, so the frame should step back — but stay reachable, and #frame=<albumId> keeps working in every option because the deep link never touches the start page. Everything below is clickable: open the entry, reach the set-up screen, go back. All pictures are generated art.

Today for reference

A full-width card with its own heading and a button, above the library.

A · A quiet row below the slideshows recommended

Pro: still on the page where people look for things, but after the slideshows, with no card chrome, no button and no accent colour. The only option that needs no extra tap to discover.

Con: it still occupies a line of the start page, and on a phone it is below the fold for a long library.

B · A "Picture frame" section in Settings

Pro: the start page is completely clean; Settings already holds the other server-dependent choice (quality of server slideshows), so the frame sits next to a sibling.

Con: hidden behind the gear — someone who never opens Settings never learns the frame exists — and a frame is something you launch, not a preference.

C · An overflow menu "⋯" in the header

Pro: one tap from the start page, nothing on the page itself, and it is the natural home for other occasional actions later (open file, export).

Con: today the menu would hold only this one item, which is thin; and it adds a second icon button next to the gear.

Why not an entry on each slideshow card? A picture frame does not play a slideshow: it reads an Immich album through the server and shows it endlessly (dev-docs/app/FRAME.md). A "Picture frame" action on a slideshow card would suggest the wrong thing, so it is left out of the options. In all three options the entry only exists while the server is on, exactly as today.
